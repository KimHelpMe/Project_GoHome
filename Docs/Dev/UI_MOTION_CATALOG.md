# UI 모션 카탈로그 — 에이전트 사용 안내

이 카탈로그는 특정 프로젝트의 화면을 그대로 복제하기 위한 목록이 아니다. 에이전트가 화면의 목적과 상태에 맞는 동작을 고르고, 여러 동작을 충돌 없이 조합한 뒤 프로젝트 기술에 맞게 구현하도록 돕는 참조다.

## 빠른 사용 순서

1. 화면의 목적, 현재 상태, 다음 상태, 입력 트리거를 확인한다.
2. 아래 **의미 패턴**에서 가장 가까운 연출 레시피 하나를 고른다.
3. 레시피의 **기본 동작**을 필요에 따라 바꾸되, 같은 요소의 같은 속성을 동시에 소유하는 모션이 없는지 확인한다.
4. 화면 내부 모션과 페이지/레이어 전환의 소유자를 나눈다.
5. 프로토타입으로 시작·중간·정착 상태, 연속 입력, 취소·역방향을 확인한다.
6. 선택한 근거와 실제 시간·easing·입력 규칙을 화면별 `motion.md`에 기록한다.

GoHome 화면 작업은 [UI Reference Pack 워크플로우](UI_REFERENCE_WORKFLOW.md)와 [UI 구조 가이드](UI_GUIDE.md)를 함께 따른다. 이 문서는 후보 조합을 찾는 데 사용하고, 그 자체가 특정 화면에 모션을 자동 추가하는 승인으로 간주되지는 않는다.

## 분류 구조

기본 동작, 화면의 의미 패턴, 재생 설정을 서로 다른 축으로 취급한다. 목록의 모든 조합을 별개의 효과 이름으로 복제하지 않는다.

### 기본 동작 — 무엇이 바뀌는가

| 동작 | 바뀌는 속성 | 주의점 |
|---|---|---|
| Fade | opacity | 가시성과 입력 가능 상태가 함께 바뀌어야 하는지 확인 |
| Translate | 위치 | 화면 계층과 탐색 방향이 일치해야 함 |
| Scale | 크기 | 중심점과 정착 크기를 명시 |
| Rotate | 회전 | 정보 화면 전체보다 도해·아이콘에 제한적으로 사용 |
| Clip / Mask | 보이는 영역 | 레이아웃 크기와 입력 영역이 가려진 상태에 맞는지 확인 |
| Color / Shadow | 색, 윤곽, 그림자 | 상태 의미가 색 하나에만 의존하지 않게 함 |
| Blur / Filter | 선명도·밝기 | 대비와 텍스트 가독성을 확인 |
| Shape / Path | 모양·경로 | 두 상태의 시각적 연결이 분명할 때 사용 |
| Parallax | 레이어별 위치 | 배경과 조작 대상의 우선순위를 유지 |

기본 동작은 구현 기술의 이름이 아니라 시각 속성의 변화다. Web에서는 CSS/WAAPI, Unreal에서는 UMG Animation·위젯 상태·상위 라우터 등 해당 프로젝트의 구조에 맞는 수단으로 매핑한다.

### 의미 패턴 — 왜 재생되는가

| 패턴 | 대표 상황 | 흔히 조합하는 동작 |
|---|---|---|
| 요소 진입·퇴장 | 버튼, 카드, 알림이 생기거나 사라짐 | Fade + 짧은 Translate 또는 Scale |
| 페이지 첫 등장 | 새 화면이 최초 표시됨 | 페이지 Fade/Translate, 필요한 콘텐츠만 시차 진입 |
| 형제 페이지 이동 | 같은 계층의 탭·하위 화면 교체 | 방향이 일치하는 Translate + 약한 Fade |
| 목록 → 상세 | 선택 대상의 맥락을 이어감 | 공유 요소 이동 또는 컨테이너 변형 |
| 모달·드로어·시트 | 화면 위에 임시 표면을 표시 | 배경 Scrim Fade + 표면의 Scale/Translate |
| 상태 피드백 | 선택, 성공, 오류, 비활성화 | 상태 변화 + 짧은 강조 동작 |
| 레이아웃·목록 갱신 | 추가·삭제·재정렬·펼침 | 새 항목 진입 + 주변 항목의 위치 보정 |
| 로딩 → 결과 | 대기 후 데이터가 준비됨 | 로딩 표시 종료 + 결과 진입, 필요 시 순차 표시 |
| 직접 조작 | 드래그, 스크롤, 스와이프 | 입력을 따르는 위치 변화 + 놓은 뒤 관성/스냅 |
| 분위기·시선 유도 | 중요 표식이나 배경 강조 | Pulse, Shimmer, 파티클 등 한 가지 보조 강조 |

Modal, Drawer, Bottom Sheet, Popup은 표면/콘텐츠 패턴이다. 이 이름만으로 모션을 결정하지 않고, 실제 진입 방향과 닫기 규칙을 함께 고른다.

### 재생 설정 — 어떻게 진행되는가

이 설정들은 단독 연출로 분류하지 않고 각 기본 동작이나 레시피에 붙인다.

- **시간·곡선**: duration, delay, easing, spring
- **순서**: simultaneous, sequence, stagger, cascade, follow-through
- **반복**: once, repeat, reverse, loop
- **제어**: cancel, interrupt, retarget, snap
- **방향**: forward/backward, 상위/하위 계층, 드래그 입력 방향

## 조합 레시피

아래 시간은 비교를 위한 시작값이다. 실제 화면 크기, 입력 속도, 프로젝트의 스타일에 맞춰 조정한다.

| ID | 레시피 | 순서와 조합 | 전형적인 제어 규칙 |
|---|---|---|---|
| `page-enter` | 페이지 첫 등장 | 페이지 Fade + Y 16px 진입 → 핵심 제목/행을 짧게 시차 표시 | 초기 진입에서 한 번 재생, 목적 화면이 바뀌면 취소 후 새 대상 적용 |
| `sibling-page` | 형제 페이지 이동 | 이전 화면 X −16px/Fade out ↔ 다음 화면 X +16px/Fade in | 탐색 방향과 이동 방향을 맞추고 빠른 재선택은 최신 목적지로 전환 |
| `connected-detail` | 목록 → 상세 | 선택 대상의 공유 요소 이동 → 상세 콘텐츠 진입 | 실제 같은 데이터 항목이 양 화면에 있을 때만 사용 |
| `modal-open` | 모달 표시 | Scrim Fade와 패널 Scale 0.96→1을 겹쳐 재생 | 열리는 즉시 배경 입력 차단, 닫기 시 이전 포커스 복원 |
| `list-update` | 목록 추가·삭제·재정렬 | 주변 행 위치 보정 + 변경 행 진입/퇴장 | 데이터 변경이 연속되면 최신 목록 상태로 재계산 |
| `loading-ready` | 로딩 → 결과 | 로딩 표시 종료 → 결과 콘텐츠 Fade/Translate, 필요할 때만 행 시차 표시 | 데이터 도착 시 취소 가능한 로딩 모션을 정리한 뒤 결과로 전환 |
| `selection-feedback` | 항목 선택 | 선택 상태 색/윤곽 변화 + 짧은 이동 또는 Pulse | 선택 데이터와 시각 상태를 같은 이벤트에서 갱신 |
| `toast` | 비차단 알림 | 짧은 Translate/Fade in → 유지 → Fade out | 같은 알림 재수신은 중복 생성보다 기존 표시 갱신 |

### 레시피 기술 중립 계약

레시피를 다른 프로젝트에 옮길 때 아래 필드를 유지하고, `owner`와 `adapter`만 대상 구조에 맞춰 채운다.

```yaml
id: page-enter
intent: 새 페이지의 표시 시작을 알린다
trigger: destination-ready
targets: [page, primary-content]
phases:
  - target: page
    changes: [opacity, translate-y]
    from: { opacity: 0, y: 16 }
    to:   { opacity: 1, y: 0 }
    duration: 220ms
    easing: ease-out
  - target: primary-content
    changes: [opacity, translate-y]
    after: 60ms
    duration: 160ms
    easing: ease-out
control:
  interrupt: cancel-and-apply-latest-destination
  reverse: use-matching-page-exit
owner: page-host
adapter: project-specific
```

플랫폼별 구현 세부값을 공통 카탈로그의 의미 정의에 섞지 않는다. 예를 들어 `translate-y`는 CSS transform, UMG Render Transform, 또는 프로젝트의 화면 라우터 전환으로 연결할 수 있다.

## 조합 규칙

- 한 화면 전환에는 **주 동작 하나**를 정하고 보조 강조는 필요한 경우 하나만 더한다.
- 같은 요소의 `transform`을 여러 독립 애니메이션이 동시에 덮어쓰지 않게 한다. 한 키프레임에 합치거나, 별도 래퍼/자식 요소에 속성 소유권을 나눈다.
- 부모 화면과 자식 콘텐츠가 같은 방향으로 동시에 크게 움직이지 않게 한다. 계층 전달이 목적이면 부모 전환이 먼저, 내용 진입은 짧은 시차로 뒤따르게 한다.
- 입력 피드백은 화면 전환보다 짧게 끝내고, 장식 모션이 선택·오류·진행 상태를 가리지 않게 한다.
- 모달/팝업은 시각 연출뿐 아니라 입력 차단, 닫기, 포커스 이동·복귀를 같은 상태 전이로 다룬다.
- 일시 효과의 취소·재진입·역방향·반복 규칙을 정의한다. 영구 반복은 명시적인 사용자 상태나 상태 표시가 필요한 경우만 사용한다.
- 페이지 교체는 페이지 호스트/라우터가, 페이지 안 요소와 목록은 해당 화면/위젯이 소유한다.

## 연출 조합을 프롬프트로 전달하기

[범용 UI 구성·모션 생성기](UI/persona-motion-examples.html)는 페이지 구성(대시보드, 목록/상세, 설정, 히어로, 미디어), 시각 언어, 화면 시나리오, 주 동작, 보조 레이어, 리듬과 타이밍을 독립적으로 조합한다. 같은 입력에 세 가지 연출 변형을 나란히 만들고, 선택한 안을 복사 가능한 구현 지시문으로 내보낸다. GoHome 화면 카탈로그가 아니며 다른 프로젝트에서 초기 UI 구조와 모션 방향을 탐색하는 도구다. 구현 대상은 기술 중립/Web/Unreal UMG/Unity UGUI 중 선택한다.

에이전트 지시문은 효과 이름만 전달하지 않고 아래 내용을 포함한다.

1. **의도와 트리거** — 무엇이 바뀌며 어떤 상태/입력에서 재생되는가.
2. **대상과 소유권** — 페이지 루트, 콘텐츠, Scrim, 장식 레이어 중 무엇을 움직이며 어느 위젯/라우터가 소유하는가.
3. **시간 구조** — 단계 순서, 겹침, 지연, 총 시간, easing과 정착 상태.
4. **기본 상태** — 각 대상의 시작·끝 값, 방향, 이동량, 확대율 등 조절 가능한 값.
5. **제어 규칙** — 재진입, 취소, 최신 목적지 적용, 역방향과 입력 가능 시점.
6. **조합 경계** — 같은 요소의 같은 속성을 중복 애니메이션하지 않으며, 보조 장식이 입력이나 정보 위계를 가리지 않음.

미리보기는 HTML/CSS Web Animation API의 시안이다. 선택한 구현 대상에 따라 기술 어댑터 지시문을 만들지만, 실제 적용 전에는 대상 프로젝트의 위젯 트리·상태·입력 소유권에 맞춰 매핑한다. 미리보기의 픽셀값이나 곡선을 검토 없이 그대로 복사하지 않는다.

## 에이전트 적용 결과물

UI 구현을 요청받으면 에이전트는 해당 화면의 `motion.md`에 최소한 다음을 남긴다.

| 필드 | 기록 내용 |
|---|---|
| Intent | 사용자가 알아차려야 하는 상태 변화 |
| Trigger | 어떤 이벤트/화면 상태에서 재생하는지 |
| Recipe | 이 카탈로그에서 선택한 ID 또는 새 레시피 근거 |
| Targets | 모션을 소유하는 실제 요소/위젯 |
| Phases | 시작·종료 상태, 속성, 순서, 시간, easing |
| Control | 입력 잠금, 취소, 재진입, 역방향, 반복 |
| Owner / Adapter | 화면 내부 위젯인지 상위 라우터인지, 대상 UI 기술에 어떻게 매핑되는지 |
| Evidence | 확인한 프로토타입 상태 또는 사용자의 명시 요청 |

GoHome에서는 위 계약을 [UI Reference Pack 워크플로우](../UI_REFERENCE_WORKFLOW.md)의 승인된 화면 계약에 반영한 뒤 UMG/BP로 구현한다. 다른 프로젝트에서는 같은 의미·제어 필드를 보존하고 해당 프로젝트의 위젯 구조와 디자인 토큰에 맞춰 어댑터를 작성한다.
